# Petri 网配液产线审计台

自动配液产线把阀门、泵和批次令牌编译为**有界 Petri 网**后，本工具在浏览器中对其做完整可达性审计：证明“每条执行都终止于验收标记且从未进入禁态”，或给出可逐步回放的反例。**纯前端实现（TypeScript + React），全程不调用任何业务后端。**

## 功能

- **模型编辑 / 导入**：2–18 个库所、1–40 个变迁；每个库所可设容量（0–3）、初始令牌、验收标记；禁态条件为子句组的析取范式（组内“且”、组间“或”）；支持 JSON 导入 / 导出与 5 个内置示例。
- **变迁语义**：按前置 / 后置整数弧原子触发，仅当令牌充足且结果不超过容量时可用；到达验收标记该次执行即结束（验收态为吸收态）。
- **完整审计**：完整探索可达状态图（默认上限 20 万状态，可调）：
  - 存在**禁态**或**非验收死锁** → 返回**步数最短、变迁编号序列字典序最小**的反例轨迹；
  - 否则存在**无限执行** → 返回**前缀最短、循环最短**并按同一规则决胜的**套索见证**；
  - 否则给出**验证通过**结论（所有执行终止于验收且未进入禁态）。
- **联锁综合（监督控制综合）**：为每个变迁标记**可控 / 不可控**（`controlled`，缺省可控；不可控＝现场必然发生的自发事件，一旦可用联锁必须放行），从初始标记计算**状态相关放行策略**：
  - 为每个可达标记计算“保证界”（受控执行到达验收的极小化极大步数上界）；**只有后继保证界严格更小的可控变迁才放行**，绕行 / 循环一律拦截；不可控变迁一旦可用即强制放行并纳入保证；
  - 成功时保证**任意被允许的执行都在有限步（≤ 初始保证界）内到达验收且不进入禁态**，并在该保证下尽可能保留可控操作；
  - 无法保证时报告**最早无法受控化解的标记、该处的不可控变迁及其必然后果**（进入禁态 / 停滞为非验收死锁 / 永久循环）；
  - 结果区可**按标记查看**每个可用变迁的放行 / 拦截决策与逐条解释，并沿用逐步回放展示收敛 / 失控见证；
  - 旧模型未填写 `controlled` 时视为全部可控，**原审计结果完全不变**。
- **反例回放**：逐步前进 / 后退 / 自动播放，页面标出每步令牌变化（库所筹码 ±n、SVG 网图令牌与弧高亮、步骤表令牌迁移）；套索循环段自动循环演示。
- **交付形态**：Dockerfile（多阶段构建 → nginx 静态托管）、Docker Compose（Web 健康检查、`HOST_PORT` 可配置宿主机端口）、名为 `verify` 的一次性验收服务（真实 Chromium 中执行场景，以退出码报告结果）。

## 快速开始（Docker）

```bash
# 仅启动 Web（默认宿主机端口 8080）
docker compose up web

# 指定宿主机端口
HOST_PORT=9090 docker compose up web

# 运行一次性验收：verify 等 web 健康后在真实浏览器中执行场景，
# 全部通过退出码 0，否则非 0；--abort-on-container-exit 让其结束后整体退出
docker compose up --exit-code-from verify --abort-on-container-exit
```

健康检查：`GET /health` 返回 `200 ok`（Dockerfile `HEALTHCHECK` 与 Compose `healthcheck` 均使用该端点）。

## 模型 JSON 格式

```jsonc
{
  "places": [                       // 2..18 个库所
    { "name": "就绪",   "capacity": 1, "initial": 1, "acceptance": 0 },
    { "name": "泵运行", "capacity": 1, "initial": 0, "acceptance": 0 },
    { "name": "过热",   "capacity": 1, "initial": 0, "acceptance": 0 },
    { "name": "完成",   "capacity": 1, "initial": 0, "acceptance": 1 }
  ],
  "transitions": [                  // 1..40 个变迁
    { "name": "启动泵", "pre": [1, 0, 0, 0], "post": [0, 1, 0, 0] },
    { "name": "停机",   "pre": [0, 1, 0, 0], "post": [0, 0, 0, 1] },
    // controlled 缺省 true（可控，联锁可拦截）；false = 不可控（现场必然发生，联锁必须放行）
    { "name": "过热",   "pre": [0, 1, 0, 0], "post": [0, 0, 1, 0], "controlled": false }
  ],
  "forbidden": [                    // 禁态条件：DNF，组内“且”、组间“或”，可为空数组
    [
      { "place": 2, "op": "ge", "value": 1 }
    ]
  ]
}
```

- `capacity`：0–3；`initial` / `acceptance`：0–capacity。
- `pre` / `post`：非负整数弧权（0–9），长度与库所数一致（缺省补 0）。
- `controlled`：布尔值，缺省 `true`；仅联锁综合使用，不影响原审计。
- `op`：`eq ne lt le gt ge` 之一；`value`：0–3。

## 审计语义约定

1. **触发**：变迁 `t` 在标记 `m` 下可用 ⟺ 对每个库所 `m[p] ≥ pre[t][p]` 且 `m[p] − pre[t][p] + post[t][p] ≤ capacity[p]`；触发是原子的。
2. **验收**：标记逐位等于验收向量即为验收态；验收态是吸收态（到达即结束，不再触发变迁），该次执行记为成功。
3. **禁态优先**：若一个标记同时满足验收与禁态条件，按违规处理（执行确实进入了禁态）。
4. **反例最优性**：禁态 / 非验收死锁反例按（步数，变迁编号序列字典序）最小返回；套索见证按（前缀长度，循环长度，序列字典序）最小返回。引擎按 (深度, 序列) 均匀代价搜索保证该最优性。
5. **无限执行**：状态空间有限，无限执行 ⟺ 可达环；套索 = 初始态到环入口的最短前缀 + 环上的最短循环。
6. **状态上限**：默认探索上限 20 万状态（界面可调）；超出时明确报告“审计中止”，不给出伪结论。

## 联锁综合语义

1. **变迁分类**：`controlled !== false` 为可控（联锁可拒绝）；`controlled === false` 为不可控——现场必然发生的动作 / 自发事件，一旦可用联锁**必须放行**并对其后果负责。
2. **保证界（rank）**：验收标记 rank = 0；若标记处有可用不可控变迁，则它们必须**全部**具有有限界，rank = 1 + max(后继界)；否则只需保留一条可控出路，rank = 1 + min(后继界)；禁态 / 非验收死锁为 ∞。值迭代从验收态反向松弛求最小不动点。
3. **放行规则**：安全标记上，不可控可用边**强制放行**；可控边当且仅当 **rank(后继) < rank(当前)** 时放行（“严格推进至验收”）。故每条放行边都令保证界严格下降，任何被允许执行 ≤ rank(初始) 步到达验收、全程不进禁态；安全非验收标记恒有放行边（不锁死）。
4. **极大性**：凡后继界严格更小的可控边全部放行，故策略在“严格下降”类中保留尽可能多的符合保证的可控操作。
5. **失败根因**：初始标记界为 ∞ 时，先在失控区域（界 ∞ / 禁态）内按最短 + 字典序定位**最早危险标记**（禁态 / 带不可控坏边者 / 死路），再沿不可控坏边给出**后果链**（进禁态 / 停滞为非验收死锁 / 永久循环）与终局标记；死锁终局另列被拦截可控选项的下游后果摘要。
6. **兼容性**：`controlled` 字段只参与联锁综合；令牌、容量、验收吸收态、禁态优先及可达图均与原审计一致，未填写时视为全部可控，原审计结果不受任何影响。

## 架构

```
浏览器（React SPA）
├── 模型编辑器（库所 / 变迁（含可控勾选）/ 禁态条件 / JSON 导入导出）
├── 审计引擎（src/petri/audit.ts，纯函数，Web Worker 中执行）
│     阶段一：按 (深度, 序列字典序) 的均匀代价搜索，完整探索可达状态，
│             命中禁态 / 非验收死锁即返回最优反例
│     阶段二：Kosaraju 求环上状态 + 逐候选最短环，产出最优套索
├── 联锁引擎（src/petri/interlock.ts，纯函数，复用同一 Worker）
│     阶段一：BFS 完整可达性（同样的令牌 / 容量 / 禁态 / 验收语义）
│     阶段二：保证界极小化极大反向松弛（不可控边 max / 可控边 min）
│     阶段三：逐边决策（强制放行 / 放行 / 拦截）+ 收敛见证
│     阶段四：失控区域两级搜索，定位最早危险标记与不可控后果
└── 结果面板（判定、统计、SVG 网图、按标记查看决策、收敛/失控回放）
```

- 无业务后端：nginx 仅托管静态文件；审计与联锁计算全部发生在浏览器（Web Worker）。
- 状态编码：容量 ≤ 3，每库所 2 bit，18 库所共 36 bit，安全编码为 JS number，配合净增量 `key' = key + Δt` 快速转移。
- 验收钩子：`window.__runAudit(model)` / `window.__runInterlock(model)` / `window.__samples` 供 `verify` 服务在真实浏览器中直接驱动引擎。

## verify 验收服务覆盖场景

健康检查端点、页面加载、四类判定（通过 / 禁态 / 非验收死锁 / 套索）、反例最短性与字典序、逐步回放与令牌变化标注、JSON 导入（合法 / 非法）、界面编辑（删除变迁）、容量阻塞语义、禁态优先、套索前缀/循环最优性、**联锁综合成功（严格推进放行 / 违章拦截 / 不可控必放 / 保证界）**、**联锁失败根因（最早失控标记、不可控变迁、禁态 / 死锁 / 永久循环后果）**、**按标记查看决策与策略回放**、旧模型兼容、页面无未捕获异常。
