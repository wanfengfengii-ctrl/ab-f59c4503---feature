# Petri 网配液产线审计台

自动配液产线把阀门、泵和批次令牌编译为**有界 Petri 网**后，本工具在浏览器中对其做完整可达性审计：证明“每条执行都终止于验收标记且从未进入禁态”，或给出可逐步回放的反例。**新增联锁综合**：为每个变迁标注“可控 / 不可控”后，从初始标记计算一份状态相关的放行策略，保证任意被放行的执行有限步到达验收且不进入禁态。**纯前端实现（TypeScript + React），全程不调用任何业务后端。**

## 功能

- **模型编辑 / 导入**：2–18 个库所、1–40 个变迁；每个库所可设容量（0–3）、初始令牌、验收标记；每个变迁可标注联锁属性（可控 / 不可控 / 未填写）；禁态条件为子句组的析取范式（组内“且”、组间“或”）；支持 JSON 导入 / 导出与 8 个内置示例。
- **变迁语义**：按前置 / 后置整数弧原子触发，仅当令牌充足且结果不超过容量时可用；到达验收标记该次执行即结束（验收态为吸收态）。
- **完整审计**：完整探索可达状态图（默认上限 20 万状态，可调）：
  - 存在**禁态**或**非验收死锁** → 返回**步数最短、变迁编号序列字典序最小**的反例轨迹；
  - 否则存在**无限执行** → 返回**前缀最短、循环最短**并按同一规则决胜的**套索见证**；
  - 否则给出**验证通过**结论（所有执行终止于验收且未进入禁态）。
- **联锁综合（可控性监督）**：当且仅当**所有变迁都已填写**可控 / 不可控属性时启用（任一未填写则维持原审计，不做综合）：
  - 不可控变迁一旦可用即**必须纳入保证**（联锁无法拒绝）；只有会**严格推进至验收**的可控变迁才被**放行**，其余一律拦截；
  - 策略由吸引子不动点（可达性博弈获胜区 + 收敛层数）综合：获胜标记上每一步（放行的可控 / 必发生的不可控）都使收敛层数严格递减，故任意被允许的执行在有限步内到达验收，且不可能进入禁态；在满足该保证的前提下**最大宽容**（放行所有严格降层的可控变迁）；
  - 无法保证时，指出**最早无法受控化解的标记**（按深度、变迁序列字典序）、该标记下**不可控变迁**及其**后果**（进入禁态 / 非验收死锁 / 在失败区域内无限循环，均为可回放见证；受困型标记还给出沿失败区域最早的危险不可控根因）；
  - 结果区可**按标记查看**允许与拦截的变迁（分类：放行 / 拦截 / 不可控·必发生 / 不可控·无法拦截 / 不可用），并可从初始标记出发**逐步回放策略**，每步解释“为何放行或拒绝”，支持手工触发与自动推演。
- **反例回放**：逐步前进 / 后退 / 自动播放，页面标出每步令牌变化（库所筹码 ±n、SVG 网图令牌与弧高亮、步骤表令牌迁移）；套索与失败后果循环段自动循环演示。
- **交付形态**：Dockerfile（多阶段构建 → nginx 静态托管）、Docker Compose（Web 健康检查、`HOST_PORT` 可配置宿主机端口）、名为 `verify` 的一次性验收服务（真实 Chromium 中执行场景，以退出码报告结果）。

## 快速开始（Docker）

```bash
# 仅启动 Web（默认宿主机端口 8080）
docker compose up web

# 指定宿主机端口
HOST_PORT=9090 docker compose up web

# 运行一次性验收：verify 等 web 健康后在真实浏览器中执行场景，
# 全部通过退出码 0，否则非 0；--abort-on-container-exit 让其结束后整体退出
docker compose up --exit-code-from verify --abort-on-container-exit
```

健康检查：`GET /health` 返回 `200 ok`（Dockerfile `HEALTHCHECK` 与 Compose `healthcheck` 均使用该端点）。

## 模型 JSON 格式

```jsonc
{
  "places": [                       // 2..18 个库所
    { "name": "就绪",   "capacity": 1, "initial": 1, "acceptance": 0 },
    { "name": "泵运行", "capacity": 1, "initial": 0, "acceptance": 0 },
    { "name": "完成",   "capacity": 1, "initial": 0, "acceptance": 1 }
  ],
  "transitions": [                  // 1..40 个变迁
    { "name": "启动泵", "pre": [1, 0, 0], "post": [0, 1, 0], "controllable": true },
    { "name": "停机",   "pre": [0, 1, 0], "post": [0, 0, 1], "controllable": false }
  ],
  "forbidden": [                    // 禁态条件：DNF，组内“且”、组间“或”，可为空数组
    [
      { "place": 0, "op": "ge", "value": 1 },
      { "place": 1, "op": "ge", "value": 1 }
    ]
  ]
}
```

- `capacity`：0–3；`initial` / `acceptance`：0–capacity。
- `pre` / `post`：非负整数弧权（0–9），长度与库所数一致（缺省补 0）。
- `controllable`（可选）：`true` = 可控变迁（联锁可拦截）；`false` = 不可控变迁（现场必然发生，只能纳入保证）；缺省 / 省略 = 旧模型，不进行联锁综合，**完整审计结果与旧版完全一致**。非布尔值导入时被校验拒绝。
- `op`：`eq ne lt le gt ge` 之一；`value`：0–3。

## 审计语义约定

1. **触发**：变迁 `t` 在标记 `m` 下可用 ⟺ 对每个库所 `m[p] ≥ pre[t][p]` 且 `m[p] − pre[t][p] + post[t][p] ≤ capacity[p]`；触发是原子的。
2. **验收**：标记逐位等于验收向量即为验收态；验收态是吸收态（到达即结束，不再触发变迁），该次执行记为成功。
3. **禁态优先**：若一个标记同时满足验收与禁态条件，按违规处理（执行确实进入了禁态）。
4. **反例最优性**：禁态 / 非验收死锁反例按（步数，变迁编号序列字典序）最小返回；套索见证按（前缀长度，循环长度，序列字典序）最小返回。引擎按 (深度, 序列) 均匀代价搜索保证该最优性。
5. **无限执行**：状态空间有限，无限执行 ⟺ 可达环；套索 = 初始态到环入口的最短前缀 + 环上的最短循环。
6. **状态上限**：默认探索上限 20 万状态（界面可调）；超出时明确报告“审计中止”，不给出伪结论。

## 联锁综合语义约定

1. **可控 / 不可控**：`controllable: true` 的变迁联锁可拒绝；`false` 的变迁现场必然发生、无法拒绝，一旦可用其后果必须全部被策略覆盖。属性缺省（旧模型）时不进行联锁综合。
2. **获胜区与收敛层数**：验收标记为第 0 层；非禁态标记 `m` 进入第 `r` 层当且仅当：① 每条不可控出边的目标都在严格更低的层（`rank < r`）；② 且 `m` 存在不可控出边，或存在一条可控出边进入更低层。该不动点按波次外扩，波次号即层数，恰为“最坏情况下被允许执行到达验收的剩余步数上界”。
3. **放行策略（状态相关、最大宽容）**：获胜标记上，凡目标层严格低于当前层的**可控**变迁一律**放行**，其余可控变迁**拦截**（进入失败区 / 禁态，或层数不严格下降——后者会留下滞留或循环空间）；不可控变迁不拦截。
4. **保证**：获胜标记上，无论触发被放行的可控变迁还是必发生的不可控变迁，层数都严格递减；层数为 0 即验收，故任意被允许的执行至多 `rank(m)` 步到达验收，且从不进入禁态（禁态不在获胜区，获胜区上没有任何被允许/必然的边进入禁态）。
5. **失证报告**：初始标记不在获胜区时，按搜索序（深度、变迁编号序列字典序）给出最早的无法受控化解标记：该标记下所有目标在获胜区之外的不可控变迁（及其后果：禁态 / 非验收死锁 / 失败区域内循环的最短见证）；若该标记本身是死锁或受困（无可放行的可控变迁），则给出受困后果与沿失败区域最早遇到的危险不可控根因。
6. **语义不变**：令牌、容量、验收（吸收态）、禁态（禁态优先）等触发与判定规则与完整审计完全一致；联锁综合只决定“允许哪些已经可用的变迁”，不改变网的执行语义。

## 架构

```
浏览器（React SPA）
├── 模型编辑器（库所 / 变迁及可控属性 / 禁态条件 / JSON 导入导出）
├── 审计引擎（src/petri/audit.ts，纯函数，Web Worker 中执行）
│     阶段一：按 (深度, 序列字典序) 的均匀代价搜索，完整探索可达状态，
│             命中禁态 / 非验收死锁即返回最优反例
│     阶段二：Kosaraju 求环上状态 + 逐候选最短环，产出最优套索
├── 联锁引擎（src/petri/interlock.ts，纯函数，同一 Worker 调度）
│     阶段一：同规则完整探索可达状态（含禁态、验收吸收态）
│     阶段二：逆邻接 + 波次队列求吸引子不动点（获胜区与收敛层数）
│     阶段三：失证时构造最早失败标记、危险不可控变迁及后果见证（BFS/DFS）
│     策略查询：getDecision(marking, t) 返回放行/拦截决定与逐条理由
└── 结果面板（审计判定与回放；联锁判定、见证回放、策略逐步回放、按标记浏览）
```

- 无业务后端：nginx 仅托管静态文件；审计与综合计算全部发生在浏览器（Web Worker）。
- 状态编码：容量 ≤ 3，每库所 2 bit，18 库所共 36 bit，安全编码为 JS number，配合净增量 `key' = key + Δt` 快速转移。
- 验收钩子：`window.__runAudit(model)` / `window.__synthesizeInterlock(model)` / `window.__interlockDecision(model, result, marking, t)` / `window.__samples` 供 `verify` 服务在真实浏览器中直接驱动引擎。

## verify 验收服务覆盖场景

健康检查端点、页面加载、四类判定（通过 / 禁态 / 非验收死锁 / 套索）、反例最短性与字典序、逐步回放与令牌变化标注、JSON 导入（合法 / 非法）、界面编辑（删除变迁）、容量阻塞语义、禁态优先、套索前缀/循环最优性；以及联锁综合：旧模型不触发综合且审计结果不变、可控属性按钮启用门控、可保证判定与获胜/失败计数、放行/拦截/不可控必发生决定、逐步放行有限到达验收、按标记查阅决定、无法保证时最早失败标记与危险不可控变迁（禁态 / 死锁后果）及见证回放、模式切换互不影响、页面无未捕获异常。
